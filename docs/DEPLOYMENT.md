# Локальная работа и публикация

## Новый компьютер

После создания удалённого private-репозитория:

```bash
git clone <REMOTE_URL> 3dprint42.ru
cd 3dprint42.ru
git lfs pull
cp .env.example .env.local
npm ci
npm run dev
```

Реальные значения `.env.local` переносятся отдельно через менеджер паролей. Не отправлять их в чат, Git, почту или мессенджер.

## Ежедневная синхронизация

Перед началом выполнять `git pull --rebase`. `npm ci` нужен после изменения `package-lock.json`. После работы запускать `npm run lint` и `npm run build`, затем коммитить осмысленный набор изменений.

## Production

- домен: `3dprint42.ru`;
- сервер: `83.217.203.91`;
- приложение: `/var/www/3dprint42`;
- активный релиз: `/var/www/3dprint42/current`;
- постоянные данные: `/var/www/3dprint42/shared/data`;
- production-переменные: `/var/www/3dprint42/shared/.env.production`;
- процессы PM2: `3dprint42`, `3dprint42-mail`;
- Nginx проксирует HTTPS на Next.js `127.0.0.1:3000`;
- TLS выпускается и продлевается Certbot.

Пароль сервера и содержимое `.env.production` в репозитории не хранить.

## Безопасная схема релиза

1. Проверить локальные `lint` и `build`.
2. Создать новую папку в `releases/`, не изменяя активный релиз.
3. Подключить shared `.env.production` и shared data.
4. Установить зависимости и выполнить production build.
5. Сделать резервную копию runtime-данных, если меняется их формат.
6. Атомарно переключить `current` на новый релиз.
7. Перезапустить PM2 и сохранить список процессов.
8. Проверить главную, админку, критические API и редиректы.
9. Сохранить предыдущий релиз для быстрого отката.

## Откат

Переключить `/var/www/3dprint42/current` на предыдущую папку релиза, перезапустить процесс `3dprint42` и проверить HTTP-ответ. Если менялся формат данных, восстановить совместимую резервную копию только после отдельной проверки.
