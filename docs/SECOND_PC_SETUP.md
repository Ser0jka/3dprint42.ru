# Подключение второго ПК

## Один раз на основном Mac

1. Создать приватный удалённый репозиторий.
2. Добавить его как `origin`.
3. Зафиксировать текущую версию проекта и выполнить первый `push`.
4. Убедиться, что большие STL/STEP отображаются как Git LFS objects.

Точный адрес репозитория подставляется вместо `<REMOTE_URL>`:

```bash
git remote add origin <REMOTE_URL>
git push -u origin main
```

## Один раз на офисном ПК

Установить Git, Node.js 20+ и Git LFS, затем:

```bash
git clone <REMOTE_URL> 3dprint42.ru
cd 3dprint42.ru
git lfs install
git lfs pull
cp .env.example .env.local
npm ci
npm run dev
```

После этого открыть `http://localhost:3000`.

## Настройки Codex на офисном ПК

В Codex открыть именно склонированную папку `3dprint42.ru`. Новый чат автоматически прочитает корневой `AGENTS.md`, а из него получит ссылки на тематические документы в `docs/`.

История старого чата не переносится, но важный проектный контекст, архитектура и решения будут одинаковыми на обоих компьютерах.

## Ежедневный порядок

Перед началом работы:

```bash
git pull --rebase
git lfs pull
```

После завершения и проверки:

```bash
git add -A
git commit -m "Кратко описать изменение"
git push
```

Не редактировать один и тот же файл одновременно на двух компьютерах до `push`, иначе придётся разрешать конфликт.

## Что не переезжает через Git

- `.env.local` и любые реальные секреты;
- production-заявки и CRM;
- файлы клиентов и сессии;
- локальные папки `data/`, `output/`, `tmp/`, `exports/`;
- пароли к серверу и админке.

Секреты переносятся через менеджер паролей. Для локальной разработки можно использовать отдельные тестовые значения; production-секреты на офисном ПК обычно не нужны.
