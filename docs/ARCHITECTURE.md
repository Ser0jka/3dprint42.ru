# Архитектура

## Стек

- Next.js 16 App Router;
- React 19 и TypeScript;
- Three.js для просмотра STL;
- `occt-import-js` для STEP/STP;
- GSAP для интерфейсной анимации;
- файловое JSON-хранилище на сервере;
- Nginx → Next.js, процессы под PM2.

Перед изменением Next.js-кода обязательно читать подходящий документ в `node_modules/next/dist/docs/`, как требует корневой `AGENTS.md`.

## Части приложения

- публичный сайт: `app/page.tsx`, `app/services`, `app/materials`, `app/cases`, `app/contact`;
- каталог: `app/katalog-3d-modelej`, `app/model-catalog.tsx`, `app/catalog-store.ts`;
- админка: `app/admin`, `app/admin-panel.tsx`;
- производственная CRM: `app/admin-workspace.tsx`, `app/workspace-store.ts`;
- кабинет команды: `app/dashboard`;
- формы и квиз: `app/project-request-form.tsx`, `app/project-quiz.tsx`;
- API: `app/api`;
- уведомления: `app/telegram-server.ts`, `scripts/mail-notifier.mjs`.

## Хранилище данных

В production `CATALOG_DATA_DIR` указывает на постоянный каталог вне папки релиза. В нём находятся каталог и категории, загрузки, заявки и вложения, CRM, настройки сайта и служебное состояние.

Эти данные нельзя коммитить или заменять при публикации. Запись JSON выполняется через временный файл и атомарное переименование, а операции внутри процесса сериализуются очередями.

## Поток заявки

1. Посетитель принимает согласие и отправляет форму или квиз в `/api/request`.
2. Сервер валидирует поля и допустимый файл.
3. Заявка и протокол согласия сохраняются в runtime-хранилище.
4. Для заявки создаётся заказ в рабочем пространстве CRM.
5. В Telegram уходит только сообщение о наличии новой заявки без имени, телефона, текста и файла.
6. Полные данные доступны после входа в админку.

## Безопасность

- административные и командные сессии подписываются HMAC и хранятся в `HttpOnly` cookie;
- production-cookie — `Secure` и `SameSite=Strict`;
- изменяющие запросы проверяют origin;
- загружаемые файлы проверяются по расширению, сигнатуре и размеру;
- секреты берутся только из окружения;
- пользовательские файлы не должны раздаваться как произвольные статические файлы.

## Ограничение текущей архитектуры

JSON-хранилище рассчитано на один основной экземпляр приложения. Перед горизонтальным масштабированием или одновременной записью из нескольких процессов данные необходимо перенести в СУБД и объектное хранилище.
